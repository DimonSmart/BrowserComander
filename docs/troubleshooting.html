Troubleshooting

Common alpha issues

The popup says the background is disconnected

  • Make sure the local server is running on http://localhost:5082.
  • Open the extension options page and confirm the configured server address.
  • Reload the extension from the browser extensions page after changing unpacked files.

The stdio bridge does not start the server

  • Keep BrowserCommander.McpStdioBridge.exe and BrowserCommanderServer.exe in the same extracted folder.
  • Start BrowserCommanderServer.exe manually once to verify the bundle itself works.
  • Confirm the client is pointing to the bridge executable you extracted, not to an old path.

The extension cannot save the server address

  • This alpha build only accepts loopback addresses such as localhost, 127.0.0.1, or ::1.
  • Use a base server URL, for example http://localhost:5082, not a tool URL or a release page URL.

ChatGPT cannot connect to the tunneled server

  • ChatGPT apps currently require a remote server URL. A plain localhost address will not work there.
  • Use the public HTTPS tunnel URL and append /mcp.
  • For BrowserCommander, do not enter /mcp/sse. The current server endpoint is /mcp.
  • If the tunnel was started with --allow-anonymous, choose No Authentication in ChatGPT.
  • Keep both BrowserCommanderServer.exe and the devtunnel host process running during the test.
  • Keep the extension options page on http://localhost:5082. The tunnel URL is only for the remote MCP client.
  • If ChatGPT starts showing Resource not found after earlier MCP calls succeeded, verify you are using the current tunnel URL and a recent BrowserCommander build. That symptom usually means the client is trying to reuse stale MCP HTTP session state through the tunnel.

How to read the server log

  • Outcome=stale_session_candidate on an MCP request completed line means the request hit /mcp with an incoming MCP-Session-Id and got 404. Usually the client reused stale MCP session state or an old tunnel URL.
  • Outcome=tunnel_reset_candidate on an MCP request completed line means the HTTP request ended with abort, cancellation, or I/O failure before MCP finished. That points to a tunnel reset, proxy interruption, or client disconnect.
  • Extension disconnect detected while command ... was pending means the browser extension lost its SignalR connection to the local server while a browser command was in flight. That is not an MCP HTTP transport failure.
  • Command ... timed out after ... while waiting for browser agent means the HTTP path stayed alive, but the browser side did not complete the command in time.
  • If you see no new MCP request started line at all for the failing step, the request probably never reached BrowserCommanderServer. In that case the problem is outside the app, usually the tunnel or the ChatGPT-side connection state.

Build output files are locked during local development

Close or stop any running BrowserCommander server, bridge, or browser instance that still has the unpacked extension loaded, then rebuild.
