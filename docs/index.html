Windows x64 public alpha

Local-first browser automation for real browser sessions.

BrowserCommander connects an authorized Chromium tab to a local MCP server. The alpha release ships as an unpacked browser extension plus a portable Windows bundle that contains the local server and the stdio bridge.

Open latest release Install the extension Install the server and CLI
Alpha scope: local loopback only, Windows x64 only, developer-mode unpacked install for Chrome and Edge.
Step 1

Download the release assets

You need two assets from the latest GitHub Release: browsercommander-extension-unpacked-vX.Y.Z.zip and browsercommander-windows-x64-portable-vX.Y.Z.zip.

Step 2

Start the local MCP side

Extract the portable bundle and either run BrowserCommanderServer.exe yourself or point your MCP client at BrowserCommander.McpStdioBridge.exe.

Step 3

Load and authorize the extension

Extract the extension zip, load it through browser developer mode, then authorize the current tab from the popup before using MCP tools.

What ships in the alpha

Piece What it does
BrowserCommander extension Connects the browser to the local server, lets the user authorize tabs, and executes commands on those tabs.
BrowserCommanderServer.exe Hosts the local HTTP MCP endpoint at http://localhost:5082/mcp and manages browser connections.
BrowserCommander.McpStdioBridge.exe Exposes the same MCP tools over stdio and can auto-start the sibling server executable from the portable bundle.

Optional remote ChatGPT testing

BrowserCommander is local-first, but you can temporarily expose the local MCP endpoint to ChatGPT developer mode through a public HTTPS tunnel. The recommended quick test flow is documented on MCP config.
